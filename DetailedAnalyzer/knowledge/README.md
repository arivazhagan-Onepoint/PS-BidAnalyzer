# `DetailedAnalyzer/knowledge/`

Reference material specific to the detailed analysis stage.

**The Onepoint capability context is not here.** It lives at
`analyzer/knowledge/onepoint_capabilities.md` and this module reads that file
directly (`config.ONEPOINT_CONTEXT_FILE`). Both stages must judge capability
against one text — a copy in this folder would drift, and the two stages would
start disagreeing about what Onepoint can do. Edit it in the analyzer's folder.

What belongs here instead: material only this stage uses — e.g. a scoring rubric
or brief template, past bid-brief examples to steer the prompt's structure, or
distilled heuristics if this stage later gets its own maintenance flow.

Anything generated by code should be added to the root `.gitignore` (as
`analyzer/knowledge/{nobid,bid}_patterns.md` are). Anything hand-authored should
be committed.
